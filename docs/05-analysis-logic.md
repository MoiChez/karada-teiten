## 0. 前提と共通定義

### できること・できないこと

| できる（参考値として） | できない |
|---|---|
| 写真上の関節の目印どうしの角度・位置関係 | 骨や関節そのものの位置（MediaPipe の点は皮膚・衣服の外見から推定した位置） |
| 自分の過去の測定との差 | 他人や「正常範囲」との比較（基準値を持たない） |
| 左右差・前後差の「方向」と「大きさ」 | 側弯・ストレートネック・骨盤のゆがみ等の診断 |
| 測定のばらつきを超える差かどうかの判定 | 骨盤の前傾・後傾の角度（骨盤の前後端の目印がない） |
| 横向きの背中の外形（輪郭）の丸み・腰のすき間 | 背骨の角度（後弯・前弯の角度）。輪郭は服・髪・体つきを含む |
| | 筋肉の硬さ・弱さ、痛みの原因、体重のかかり方の実測 |

### 座標系

- **画像座標**: MediaPipe の正規化座標 `(x, y)` に画像の幅・高さを掛けた **ピクセル座標**。原点は左上、x は右、y は下が正。角度は縦横比のゆがみを避けるため必ずピクセル座標で計算する
- **鉛直の基準**: 画像の縦方向を鉛直とみなす（カメラが垂直に構えられている前提）。アプリ内撮影では端末の傾きを記録し、3° を超えたら注意を出す
- **被写体の左右**: MediaPipe の `left_*` は被写体自身の左。正面写真では、被写体の左は通常は画像の右側に写る。符号は画像の向きに頼らず、ランドマークから求める
  `sLat = sign((L肩.x − R肩.x) + (L股.x − R股.x))`（被写体の左が画像の右なら +1）
- **側面の向き**: `f = sign((鼻.x − 耳.x) + (足先.x − かかと.x))`（顔が画像の右を向いていれば +1）。前方 = `f` の方向
- **側面の近い側**: 左右の耳・肩・股関節・膝・足首・かかと・足先の visibility の平均が高い方を「カメラ側の半身」とし、側面の計算はその側の点だけを使う

### 前処理

1. 各点の信頼度 `v = min(visibility, presence)`（値がなければ 1）。手動補正した点は `v = 1` として扱い、補正済みの印を付ける
2. 点の扱いを 3 つに分ける
   - **写っている点**: 画像の中にあり `v ≥ 0.5`
   - **推測した点**: `v < 0.5`（隠れている・暗い）か、画像の外に少し出ている点。MediaPipe が推測した位置をそのまま使い、誤差を広く見込む（下の「測定のばらつき」）
   - **使わない点**: 画像の幅・高さの 25% を超えて画像の外に出ている点。計算に使う点にこれがあれば、その指標は **評価不可**
   - 耳と目尻のように代わりの点を選ぶときは、写っている点を優先する
   - 利用者が点を手で直すことは前提にしない。このアプリは精密な測定より、自分の姿勢に目を向けて体を動かす習慣や専門家に相談するきっかけを目的にしているため、写真が多少欠けていても推測で値を出す
3. 体の大きさの基準
   - `H` = 耳の中点からかかとの中点までの縦の距離（正面）/ カメラ側の耳からかかとまでの縦の距離（側面）
   - `T` = 肩の中点と股関節の中点の距離（胴の長さ）

### 測定のばらつき（不確かさ）

基準値を作らない代わりに、「その差が測定のばらつきを超えているか」を判定する。

- 仮定: 各ランドマークの位置は、縦横それぞれ標準偏差 `σ = 0.005 × H` でずれうる（体の高さの 0.5%。身長 170cm なら約 0.85cm）。これは医学的な基準ではなく、**判定のための工学的な仮定** で、[src/domain/constants.ts](../src/domain/constants.ts) で変更できる
- 推測した点は `σ = 0.04 × H` とする。全身が写った実在の人の写真 20 枚の足元を切り落として（足首の高さ / すねの中ほど）測り直すと、推測した膝・足首・かかと・足先は、切る前の位置から H の約 4% / 6%（距離の二乗平均）ずれた。1 方向あたりに直して 0.04 とした。この σ で、切り落とした写真の値と切る前の値の違いは、見込んだばらつきの 0.2〜1.0 倍（指標ごとの二乗平均）に収まった
- 計算: 使用する点に上記のずれを乱数で 150 回与えて指標を再計算し、その標準偏差を `uncertainty`（1σ）とする。乱数のシードは固定し、同じ入力からは同じ結果になる
- 判定: `|値| > 2 × uncertainty` なら **差が見られる（noticeable）**、それ以下なら **測定のばらつきの範囲内（within_noise）**
- 判定するのは、0 が「差なし」と言える指標（正面の左右差）だけ。横向きの前後の位置（S1〜S5）と複合スコア（C1・C2）は、0 が良い姿勢とは言えないので 1 回の測定では判定せず、**位置の記録（descriptive）** とする（2 を参照）
- 比較: `|今回 − 前回| > 2 × √(σ前回² + σ今回²)` なら変化あり
- 以前の高精度モード（5 枚の平均。版 0.6 までの記録）でも σ は 0.005 × H を下限にする。平均した後の揺れがそれを超えるときだけ広げる（3d を参照）
- 背中の輪郭の指標（S8・S9）は、輪郭から取った点（接点・頂点など）を `0.003 × H` だけ前後にずらす（3f を参照）

### 信頼度

`confidence = min(使用点の v) × 品質係数 × 指標ごとの上限`

- 推測した点の v は 0.4 を上限にする。推測した点を使う指標の信頼度は「低」になる

- 品質係数: 端末の傾き 0.8、ぶれの可能性 0.8、暗い/明るすぎ 0.85、コントラスト不足 0.9、小さく写っている 0.85、複数人 0.9、体全体の大きな傾き 0.7（該当するものを掛け合わせる）
- 体の向きが合っていない写真（4 の `orientation_front` / `orientation_side`）は、その面の指標をすべて評価不可にする。面全体の信頼度には 0.6 を掛ける
- 表示: 0.75 以上「高」、0.5 以上「中」、それ未満「低」

## 2. 側面の指標

側面は「カメラ側の半身」の点だけを使う（耳 E、肩 S、股関節 P、膝 K、足首 A、かかと Hl、手首 W）。

**1 回の測定では判定しない**。S1〜S5 は「耳が肩の真上」「肩が股関節の真上」などを 0 とした値だが、0 が良い姿勢とは言えない。実在の人の横向き写真 8 枚で試したところ、8 人全員が「猫背傾向に関連する特徴: 差が見られる」、6 人が「頭部前方位傾向: 差が見られる」になり、ほぼ全員に出る判定は役に立たないと分かった。そのため S1〜S5 と複合スコア（C1・C2）は、値と向きを **位置の記録** として残し、「差が見られる / ばらつきの範囲内」は付けない。前回（または意識した姿勢）と比べて、ばらつきを超えて 0 に近づいたか離れたかだけを伝える（[07-correction-compare-3d.md](07-correction-compare-3d.md) の 2-D、この文書の 3e）。

### S1. 頭部前方位の参考指標 `side_head_forward`
| 項目 | 内容 |
|---|---|
| 使用点 | E、S、P（T 用） |
| 数式 | `θ = atan2((E.x − S.x)·f, S.y − E.y)`（耳-肩ラインの鉛直からの前傾角）。正規化値 = `(E.x − S.x)·f / T × 100` |
| 意味 | + は耳が肩の真上より前にある。値が大きいほど頭が前に出ている方向 |

| 限界 | 臨床でいう頭蓋脊椎角（耳珠と第 7 頸椎）とは目印が違う。肩の点は腕の位置でも動く |
| 測定不能 | E または S が評価不可 |

|---|---|
| 使用点 | カメラ側の耳 E と目尻 Y（3 または 6） |
| 数式 | `θ = atan2(Y.y − E.y, (Y.x − E.x)·f)`（度）。目尻が耳より前に写っていなければ評価不可 |
| 意味 | + は目尻が耳より下（顔が下を向く方向）。良し悪しは判定しない（記述のみ） |
| 限界 | 顔の形や点の推定位置により、まっすぐ前を見ていても 0 になるとは限らない。耳と目尻が近いため、ばらつきが大きい。主に前回との違いと、撮影時の顔の向きの確認に使う |
| 測定不能 | E または Y が評価不可 |

### S7. 骨盤の前後傾 `side_pelvis_tilt`
初期版では **推定できない**（状態: unsupported）。MediaPipe には骨盤の前端（上前腸骨棘）と後端（上後腸骨棘）の目印がないため。画面では理由を表示し、代わりに S4 を参考として示す。

### S8. 背中上部の丸み（背中の輪郭） `side_back_upper`
| 項目 | 内容 |
|---|---|
| 使用するもの | 背中側の輪郭（3f）、カメラ側の肩 S と股関節 P の高さ |
| 数式 | 肩の高さの輪郭上の点 T と、`S.y + 0.6 × (P.y − S.y)` の高さの輪郭上の点 B を結ぶ。T〜B の間で、線 TB から最も後ろへ出ている輪郭の点までの距離を深さ h、TB の長さを L として、`θ = 4·atan(2h / L)`（度）。同じ深さ・長さの円弧の両端の接線がなす角にあたる |
| 補足値 | h（体の高さに対する %、身長があれば cm） |
| 意味 | 大きいほど、肩から胸の下までの背中の外形が後ろへ丸く出ている。良し悪しは判定しない（記述のみ） |
| 区間 | 0.6 は「おおよそ胸の背骨の範囲」として決めた区間の取り方で、基準値ではない |
| 限界 | 背骨の角度（レントゲンで測る後弯の角度など）とは別物。服のゆとり、背中にかかる髪、肩甲骨の出方、体つきで変わる |
| 測定不能 | 輪郭がない・途切れている、S か P が評価不可、腕や手が輪郭に重なっている（3f） |

### S9. 腰のすき間の深さ（背中の輪郭） `side_back_lower`
| 項目 | 内容 |
|---|---|
| 使用するもの | 背中側の輪郭（3f）、カメラ側の肩 S と股関節 P の高さ |
| 数式 | 肩の高さから `P.y + 0.12 × H` までの輪郭に、後ろから定規を当てる（輪郭の後ろ側の凸包）。`S.y + 0.45 × (P.y − S.y)` 〜 `P.y + 0.02 × H` の範囲で、定規から最も前へ離れている輪郭の点までの距離 d。値は `d / H × 100`（%） |

## 3. 複合指標（説明可能なスコア）

複合指標は、上の指標を「表示用スケール」で割って平均したもの。表示用スケールは単位をそろえるための値で、**医学的な基準ではない**。自分の過去との比較に使う。

### C1. 猫背傾向スコア `composite_kyphosis`
`(S1角度 / 10° + S2角度 / 5° + S3 / 20%) / 3`（S3 が評価不可なら残り 2 つの平均。S1 と S2 は必須）

### C2. 反り腰関連スコア `composite_swayback`
`(S4 / 3% + S5角度 / 5° + (−S2角度) / 5°) / 3`（S4 と S5 は必須）

いずれも内訳（各成分の値）を画面に表示する。不確かさは同じ乱数摂動の方法で求める。スコアも 1 回の測定では判定せず、位置の記録として残す（2 の冒頭を参照）。

## 3b. 長さ（cm の目安）

位置のずれ・高さの差を表す指標は、計算のときに長さ `len`（ピクセル、値と同じ向きの符号付き）も返し、体の高さ H に対する比 `offset.frac = len / H` と、その不確かさ `offset.sigma`（同じ乱数摂動の標準偏差 / H）を保存する。

- cm の目安 = `offset.frac × 身長 × 0.91`
- 0.91 は「H（耳〜かかとの点）が身長の何割か」の概算（[src/domain/constants.ts](../src/domain/constants.ts) の `H_TO_STATURE`）。身体寸法比の文献値（目の高さ ≈ 身長の 93.6%、Drillis & Contini）から、耳はそれより少し下、かかとの点は床より少し上として決めた。数 % の誤差を含む
- 身長がプロフィールにないときは cm を出さない
- % の指標と、肩・骨盤付近の高さの差、頭の前後位置は、身長があれば cm を主に表示する。それ以外の角度の指標は角度を主にし、cm は項目別の一覧に補足として出す

## 3c. 向きつきゲージ

[src/domain/gauge.ts](../src/domain/gauge.ts)。各指標を 7 マスで示す。

- 中央のマス = `|値| ≤ 2σ`（測定のばらつきの範囲。「差が見られる」の判定と同じ境界）
- 外側へ 1 マス = ばらつき 2 つ分（2σ）ずつ。`段階 = min(3, ceil((|値|/σ − 2) / 2))`
- **医学的な基準値ではない**。その差が測定のばらつきに比べてどれだけはっきりしているかを表す
- 並び: 正面は写真と同じ（写っている人の右が画面の左）、横向きは前が左
- 肩・骨盤付近の高さは、上がっている側にマスを置き「右が上 / 左が上」と書く
- 判定する指標を先に、位置の記録（S6・S6b）を後に「良し悪しは判定しません」と見出しを付けて並べる
- 前回の値があれば、前回のマスを点線の枠で重ねる（結果画面は直前の測定、比較画面は比較相手）

## 3c2. 鏡の前で自撮りした写真

- **左右**: 鏡に映った姿は左右が反対なので、撮った写真（選んだ写真も）を左右反転してから推定・保存する。以降の計算は、ふつうに撮った写真と同じ
- **スマホを持つ腕**: 腕の前方位置（S3）は評価しない（猫背傾向スコアは腕を除いた成分で計算する）
- **注記**: 肩の高さの左右差（スマホを持つ側の肩が上がりやすい）、頭の左右傾き・頭部前方位・頭の前後傾き（撮る瞬間に画面を見ると変わる）に注記を付ける
- **比較**: 置いて撮った回と自撮りの回を比べるときは、カメラの高さと腕の位置が違うことを注意する

## 3d. 高精度モード（続けて撮って平均する。版 0.6 までの記録）

版 0.7 からは 1 枚撮りに統一した。以前の記録の表示と比較のために、計算はそのまま残している。

[src/domain/burst.ts](../src/domain/burst.ts)。

- **撮り方**: 動かずに立ったまま、5 枚を 0.5 秒間隔で撮る（約 2 秒）。撮影中は映像のコマをすぐに切り出し、画像の圧縮はあとでまとめて行って間隔を保つ
- **そろえ方**: 正面は耳・肩・股関節・膝・足首・かかと（12 点）、横向きはカメラ側の耳・肩・股関節・膝・足首・かかと（6 点）を使う。各写真の点を、重心を原点・重心からの距離の二乗平均を 1 にそろえる（立ち位置と距離の違いを取り除く。回転はそろえない＝傾きは姿勢として残す）
- **平均**: そろえた形の平均を、平均に最も近い 1 枚（代表の写真）の位置と大きさに戻したものを `landmarksRaw` にする。点ごとに、その写真で検出できた枚だけで平均する。写真は代表の 1 枚だけを残す
- **写真ごとの揺れ**: `spreadFrac = √(残差の二乗和 / 自由度) × 代表の大きさ / H`。自由度 = `(枚数 − 1) × (2 × 点の数 − 3)`（各枚の位置 2 と大きさ 1 の分を引く）。自由度が 10 未満なら求めない。推定の揺れと体の小さな揺れを含む
- **判定に使う σ**: `max(0.005, spreadFrac / √枚数)`。平均で小さくなるのは写真ごとの揺れだけで、服や体格・端末の傾きによる推定のずれは続けて撮っても減らないため、前提（0.005）より狭くはしない。平均した後の揺れが前提を超えるとき（撮影中に動いた、暗いなど）だけ広げる
- **効果**: 判定の幅は変えないが、値そのものの揺れは平均で小さくなる。前回との比較で、たまたまの揺れによる「変化あり」が出にくくなる
- **1 枚ごとの値**: 各撮影の点からも指標を計算して `burstValues` に残す（表示用）。平均した点を手動補正したときは、同じだけ各撮影の点も動かす
- **2 枚以上で検出できなかったとき**: 検出できた 1 枚で、従来どおり 1 枚として分析する

## 3e. いつもの姿勢と意識した姿勢

[src/domain/conscious.ts](../src/domain/conscious.ts)。同じ日に「自分が良いと思う姿勢」でも撮り、いつもの姿勢と比べる。どちらも同じ計算で指標を出す。

判定する指標ごとに、いつもの値 a、意識した値 b、閾値 T = 2 × √(σa² + σb²)（前回との比較と同じ）として:

| 分類 | 条件 | 提案 |
|---|---|---|
| ばらつきの範囲まで小さく | a に差あり、b の絶対値が a より T 以上小さい、b はばらつきの範囲内 | 意識づけ |
| 小さくなるが残る | a に差あり、b の絶対値が a より T 以上小さい、b にも差あり | 意識づけ + 体を動かすメニュー |
| 変わりにくい | a に差あり、絶対値の差が T 以下 | 体を動かすメニュー |
| 大きくなる | b の絶対値が a より T 以上大きい（a に差がなく、意識すると差が出た場合を含む） | 意識の向け方を確かめる |
| 反対の向きへ | 向きが反対、b にも差あり、b − a の大きさが T を超える | 意識の向け方を確かめる |

- 横向きの前後の位置（S1〜S5、C1・C2）は 1 回の測定で判定しないので、上の表ではなく値の変わり方だけで分ける。絶対値が T を超えて小さくなれば「小さくなる」（意識づけ）、T を超えて大きくなれば「大きくなる」、向きが反対になり b − a の大きさが T を超えれば「反対の向きへ」（どちらも意識の向け方を確かめる）。変わらなければ一覧に出さず、「差が残る」とも言わない
- どちらの姿勢でも差がない指標は一覧に出さず、数だけ示す。位置の記録（S6・S6b）は、ばらつきを超えて変わったものだけ文で示す
- 仮説は断定しない。変わりにくい差は「体の動かしやすさ（柔軟性や筋力）、骨格の個人差、意識の向け方など、いくつかの可能性があり、この結果だけでは理由は分からない」とする
- 提案: 意識で小さくなった特徴は「姿勢のコツ」のメニューに +1、意識しても残った特徴は「ストレッチ・モビリティ・軽い運動」に +0.75。習慣の提案に「意識した姿勢を 1 日の決まった場面で思い出す」「良い姿勢をつくるとき動かしすぎていないか鏡で確かめる」を加える

## 3f. 背中の輪郭

[src/domain/backContour.ts](../src/domain/backContour.ts)。横向きの写真だけで行う。

- **人の領域**: MediaPipe Pose Landmarker の segmentation mask（人である確からしさ 0..1、写真と同じ大きさ）を使う。モデルは骨格推定と同じで、追加のモデルはない
- **取り出し方**: 肩の高さより `0.08 × H` 上から、股関節の高さより `0.14 × H` 下まで、`0.004 × H` おきの各行で、胴の中心（肩と股関節を結ぶ線）から画像の左と右へそれぞれたどり、値が 0.5 を下回るところを端とする。端の位置は、境目の 2 画素の値を線形補間して画素より細かく求める。体の中の小さな抜け（写真の幅の 0.6% 以内）は飛ばし、離れた腕などはつなげない。範囲に余白をとるのは、手動補正で肩や股関節の位置が動いても足りるようにするため
- **保存**: 体の左端と右端の点（正規化座標）を `PlaneRecord.outline` に保存する。どちらが背中側かは計算のたびに顔の向きで決める（顔が画像の右向きなら左端）ので、確認画面で向きを切り替えても正しい側を使う。写真を保存しない設定でも、輪郭の線だけで計算し直せる
- **以前の高精度モード（版 0.6 までの記録）**: 5 枚それぞれから左端・右端を取り、骨格と同じそろえ方（位置と大きさ）で代表の写真の座標へ移し、高さごとに x を平均する（半分以上の写真で値がある高さだけ）
- **腕・手の確認**: カメラ側・奥側の肘、上腕の中点、手首、手の点のうち確認できたものが、測る区間の高さで背中の輪郭から `0.03 × H` より近ければ、腕が輪郭に重なっている可能性があるとして評価不可にする
- **ばらつき**: 輪郭の端の位置の想定誤差を `0.003 × H`（1σ）とする。端は画素より細かく求まるため骨格の点の想定（0.005 × H）より小さくした工学的な目安で、体の高さが 1,000〜1,500 画素の写真で 3〜5 画素にあたる。真横から撮れている実在の人の写真 4 枚を左右反転して測り直し、値の違いがこの想定から求めたばらつきの 0.5 倍（背中上部）〜1.1 倍（腰のすき間）になる大きさにした（以前の 0.002 では腰のすき間が 1.7 倍あり、小さすぎた）。4 枚だけの確認なので、目安として扱う。輪郭から取った点（T・B・頂点、定規の 2 つの接点、いちばん深い点）をこの大きさで前後にずらし、肩・股関節の点は骨格と同じ σ でずらして、150 回の再計算の標準偏差を不確かさとする。以前の高精度モードの記録では、1 枚ごとの値の標準偏差 ÷ √枚数 がこれより大きければ、それに広げる（狭めはしない）
- **含まないもの**: 服・髪・立ち方の違いによる外形の変化。日を変えて比べるときは、同じような服装・髪型で撮る必要がある

状態は指標の判定をそのまま使う（差が見られる / ばらつきの範囲内 / 位置の記録 / 評価不可 / 未測定）。横向きの特徴（頭部前方位傾向 〜 膝過伸展傾向）は、根拠の指標を 1 回の測定で判定しないので、測れたときはいつも **位置の記録（recorded）** になり、事実の文（どちらへ、どのくらい）だけを出す。文章は「観測された事実」だけを書き、原因は「考えられる要因（仮説）」に分ける。

## 6. 生活習慣との関連仮説

プロフィールの生活パターン・活動量・疲労感と、**差が見られた** 特徴の組み合わせで、仮説の文章を出す（[src/domain/hypotheses.ts](../src/domain/hypotheses.ts)）。例:

- 肩の左右差 + かばんを片側で持つ → 「いつも同じ側でかばんを持つ習慣が、肩の高さの左右差に関係している可能性があります」

いずれも「可能性」「かもしれません」と書き、断定しない。該当する生活パターンがなければ仮説は出さない。

横向きの特徴は 1 回の測定では「位置の記録」で、「差が見られた」にはならない。そのため、横向きの特徴にもとづく仮説（頭部前方位 + デスクワークなど。ルールは残してある）と、横向きの写真だけにもとづく初回の運動の提案は出ない。初回の提案は、正面で差が見られた特徴と、プロフィールの気になる部位・目標から選ぶ。2 回目からは、前回より大きくなった横向きの位置を提案の理由に使う。

## 7. 動き（スクワット・ローイングエルゴ・固定式の自転車）

入口は [src/domain/motion.ts](../src/domain/motion.ts)、種目によらない土台は [motionCore.ts](../src/domain/motionCore.ts)、種目ごとの値と区切りは [motionSports.ts](../src/domain/motionSports.ts)、器具の前提は [motionConstraints.ts](../src/domain/motionConstraints.ts)。横から撮った動画を 1 コマずつ推定し、体の点の時系列から関節の角度を求めて、1 回（1 本・1 回転）ごとに区切る。正常範囲とは比べず、良し悪しも判定しない。値は自分の過去の記録と比べるためのもの。版 0.8〜0.10 の歩き方は、版 0.11 で外した。以下、とくに断りのないものは 3 種目共通。

- **入力**: アプリで撮る（5 秒の合図のあと最長 20 秒。「撮り終える」で止める。コマを JPEG（長い辺 720 ピクセル）で一時的にためて、撮り終わってから推定する）か、撮った動画を選ぶ（最初の 20 秒を 1/30 秒ごとに取り出す）。推定は動画用の推定器（前のコマの位置を手がかりに追う）で、画面上の点と、推定モデルの 3D の点（メートル、腰の中心が原点）の両方を保存する
- **映像の向き**: 写っている人の向き（股関節→肩。足首→股関節と 45° 以上食い違うコマでは決めない）で 90° 単位に回して起こす。5 コマのうち 3 コマ以上が同じ向きを示したときだけ回す。アプリで撮ったときは端末の傾きも戻す
- **カメラ側の半身と顔の向き**: すべてのコマの、左右の耳・肩・股関節・膝・足首・かかと・足先の見えている度合いの合計が大きい方をカメラ側とし、計算はその側の点だけを使う。顔の向きは「鼻 − 耳 + 足先 − かかと」の横の位置の中央値の符号
- **使うコマ**: カメラ側の肩・股関節・膝・足首が使える点（3 章の「使わない点」でない）で、肩が股関節より上のコマ（スクワットと自転車は、膝が足首より上も）。0.25 秒より長い途切れがあれば、前後を別の区間にする
- **手で直した点**: 直したコマの点をその位置に置き（見えている度合いは 1）、なめらか化の後もその位置のままにする。推定した点（frames）は書き換えない
- **なめらか化**: 点の座標を、区間の中だけ、ガウスの重み（前後 2σ コマ）でなめらかにする。σ はスクワット 1.5、エルゴ 1.0、自転車 0.7 コマ（速い動きほど弱くする。自転車で 1.5 にすると、90 回転/分で膝の角度の山と谷が最大 9° 削られた）
- **器具の前提**（エルゴ・自転車。なめらか化の後。手で直した点は書き換えない）:
  - エルゴの足首: 足首の位置のばらつき（x・y の四分位範囲の大きい方）が脚の長さの 6% 以内なら、フットプレートに留まっているとして中央の位置に置く。超えたら（手持ちで撮ったなど）使わない
  - エルゴの腰: 股関節の高さを前後の位置に対して一直線（最小二乗）に当て、傾きが 0.5 未満で、線からのずれの四分位範囲が脚の長さの 5% 以内なら、レールの上を動くとして線の上に乗せる
  - 膝（エルゴ・自転車）: 股関節〜足首が長い方から 3 割のコマ（脚がよく伸びたコマ）で、太もも（股関節〜膝）とすね（膝〜足首）の長さの中央値を測る。どのコマでも、股関節を中心に太ももの長さ、足首を中心にすねの長さの円を描き、2 つの交点のうち推定した膝と同じ側を膝とする（届かないときは、脚をまっすぐ伸ばした位置）。体が縮んだキャッチで推定の膝が股関節の方へずれ、正解のある人形の動画でキャッチの膝が 30° 小さく出たため（置き直した後は 1.5° の差）
  - 使った前提は記録に残し、結果の「撮影の情報」に書く
- **値**（コマごと。カメラ側の点、傾きを戻したピクセル座標）:
  - しゃがむ深さ（%）: `(L − (足首.y − 股関節.y)) / L × 100`。L は「足首.y − 股関節.y」の高い方から 1 割の値（立っているときの股関節〜足首の高さ）
  - 膝の曲がり: `180° − 股関節・膝・足首の内角`（脚がまっすぐで 0°）
  - 股関節の曲がり: `180° − 肩・股関節・膝の内角`（上体と太ももが一直線で 0°）
  - 上体の前傾: 股関節→肩の線の、鉛直から顔の向きへの角度
  - すねの前傾: 足首→膝の線の、鉛直から顔の向きへの角度
- **エルゴの値**（コマごと）: 膝・股関節・上体（上と同じ）、ひじの曲がり（`180° − 肩・ひじ・手首の内角`）、手の位置（手首が足首からどれだけ後ろか。脚の長さに対する %）、腰の位置（股関節が足首からどれだけ後ろか。同じく %）
- **エルゴの区切り**: 手の位置の谷（深さ 15 ポイント以上）をキャッチとし、キャッチから次のキャッチまで（1.2〜6 秒）を 1 本とする。その間で手の位置がいちばん大きいところをフィニッシュとする
- **エルゴの 1 本ごとの値**: ストロークレート（60 ÷ 1 本の秒数）、ドライブ（キャッチ→フィニッシュ）とリカバリー（フィニッシュ→次のキャッチ）の時間とその比、キャッチの膝・股関節・上体、フィニッシュの上体（後ろが −）とひじ、手の動いた幅、脚・上体・腕が「半分動いた」時刻（ドライブの %。膝の曲がりが半分戻った時刻、上体の傾きがキャッチとフィニッシュの中間を過ぎた時刻、ひじの曲がりが半分になった時刻。動く順番の目安で、早い・遅いは判定しない）
- **自転車の値**（コマごと）: 膝・股関節・上体（上と同じ）、足首の角度（膝・足首・足先の内角。つま先を下げるほど大きい）
- **自転車の区切り**: 膝の曲がりの谷（深さ 15° 以上）を下死点とし、下死点から次の下死点まで（0.3〜3 秒）を 1 回転とする。その間で膝がいちばん曲がったところを上死点とする
- **自転車の 1 回転ごとの値**: ケイデンス（60 ÷ 1 回転の秒数）、下死点と上死点の膝、股関節のいちばん開いたとき・閉じたとき、下死点の足首、足首の角度の動いた幅、上体の前傾の平均
- **スクワットの区切り**: 深さが 15% 以上になってから 8% 未満に戻るまでを 1 回とする。前後のいちばん浅いところより 3% 深くなった時刻を動き始め、3% まで戻った時刻を立ち上がり終わりとし、いちばん深い時刻までをしゃがむ時間、そこからを立ち上がる時間とする。撮り始めにすでにしゃがんでいた回と、撮り終わりに立ち上がっていない回は数えず、そのことを知らせる
- **1 回ごとの値**: 区間の中の、深さ・膝・股関節・上体・すねの最大と、しゃがむ時間・立ち上がる時間
- **平均とばらつき**: 回ごとの値の平均。比べるときのばらつきは「回ごとの標準偏差 / √回数」で、下限は角度 2°・深さ 2 ポイント・時間 0.1 秒（推定の点の揺れから見た工学的な目安で、正常範囲ではない）
- **前回との比較**: 差が、2 回の揺れを合わせた幅（二乗和の平方根）の 2 倍を超えたら「差が見られる」
- **真横の確認**: 立っているコマの「左右の股関節の間隔 / 胴の長さ」の中央値が 0.2 を超えたら、真横から撮れていない可能性を知らせる（値は出す）。肩ではなく腰で見るのは、バーベルを担ぐと腕が上がり、肩の点が左右に広がって見えるため（バーを担いで真横から撮った写真で、肩では 0.42、腰では 0.14）。実在の人の写真では、腰の値は真横 0.01〜0.16、斜め後ろ 0.30 前後、正面 0.26〜0.45 だった
- **脚が隠れているとき**: カメラ側の股関節・膝・足首の、見えている度合いの中央値が 0.5 未満なら、その部位の名前を出して、推測した位置で計算していることを知らせる（ラックの柱・器具・体の陰）
- **再生**: 撮った動画（コマの画像）、3D の体、角度のグラフを 1 つの時計で動かす。動画は撮るときに「残す」を選んだときだけ端末に保存し、残さないときはページを閉じるまでメモリに持つ
- **並べて比べる**: 2 つの記録のそれぞれ選んだ 1 回を、始めから終わりまで 0〜100% にそろえ、1 つの進み具合（0〜100%）から各記録の時刻を求めて動画・3D を動かす。平均の曲線は、各回を 101 点に引き直して平均したもの
- **動画の書き出し**（[MotionVideoExport.tsx](../src/components/MotionVideoExport.tsx)）: 720×1280 の canvas に、コマごとに、撮った動画のコマと重ね表示（画面と同じ描き方）、画面に出ている 3D の canvas（描いた内容を残す設定にして写す）、今の値、グラフと今の時刻の線を描き、canvas の映像をブラウザの録画（MediaRecorder、毎秒 30 コマ、5 Mbps）で録る。再生の時計を最初から終わりまで動かしながら描くので、録画は再生と同じ時間かかる。形式は MP4（H.264）を優先し、できなければ WebM。画面を離れたら録画をやめ、ファイルは作らない
- **書き出し**（[motionExport.ts](../src/domain/motionExport.ts)）: コマごとの値（時刻・各角度・何回目・出来事・手で直した点）、1 回ごとの値、記録そのもの（JSON。座標の説明つき、動画は含めない）。CSV は表計算ソフトで開けるよう BOM つき UTF-8
- **太ももの傾き**（スクワット）: 股関節と膝の点を結ぶ線の、水平からの角度。股関節が膝より下で + （パラレルより深い）。いちばん深いところの値を 1 回ごとに出す。分類（浅い・深い）の言葉は付けず、符号だけで示す
- **重心と負担**（スクワット。[motionLoad.ts](../src/domain/motionLoad.ts)。すべて仮定の上に立つ推定で、測った値ではない）:
  - 体の値: 身長・体重・持つ重さ（入力がなければ 170 cm・70 kg・0 kg を仮定し、「仮定」と出す）。長さは、立っているときの耳〜かかとの高さ（高い方から 1 割の値）を身長 × 0.91 とみなしてメートルにする
  - 重心: Winter (2009) の体節の質量比（頭頸部 0.081・胴 0.497・上腕 0.028・前腕と手 0.022・太もも 0.100・すね 0.0465・足 0.0145。手足は片側）と重心の位置（近位から、上腕 0.436・前腕と手 0.682・太もも 0.433・すね 0.433・足 0.5、胴は股関節と肩の中点、頭は耳の点）で、横から見た画面の上の点から求める。奥側の手足はカメラ側と同じ位置とみなす。持つ重さは手首の位置に足す
  - 重心の真下の位置: 重心の前後の位置を、かかと 0%・つま先 100% で表す
  - 床からの力: 鉛直で、大きさは（体重 + 重さ）×（重力 + 重心の上下の加速度）。加速度は前後 3 コマの差から求め、重力の ±0.5 倍に抑える。基準の仮定は、足圧中心が推定の重心の真下（かかと 0〜つま先 1 の位置。足の外に出るときは足の端）、左右の脚に半分ずつ。ゆっくりした動きでは体がほぼつり合っているため。仕様書は足の真ん中（0.5）を基準にしていたが、人形の動画で重心が足の 78% にあるのに 0.5 に置くとつり合わず、幅が 0.04〜1.45 倍まで広がったため変えた
  - 負担（片脚、関節を伸ばす向きの力のモーメント）: 足圧中心にかかる床からの力と、関節より先の体節（足・すね・太もも）の重さによる、関節のまわりのモーメント（体節の加速度は入れない準静的なモデル）。股関節 ÷ 膝の比を出す。膝のモーメントが 10 Nm 未満のコマ（ほぼ立っている）は出さない
  - 幅: 足圧中心を、重心の真下から足の長さの ±0.25（5 段。足の外には出さない）、カメラ側の脚への配分を 0.4〜0.6（3 段）に動かした 15 通りの比の最小〜最大。基準の値は必ず幅の中に入れる
  - 要求度（0〜1）: `clip(0.7 × |モーメント| / 基準 + 0.3 × 曲がりの度合い, 0.05, 1)`。基準は（体重 + 重さ）× 重力 × 身長の 10%（脚は片脚ぶんで半分、背中は上体と重さぶん）。曲がりの度合いは膝・股関節 120°、上体の前傾 60°、すねの前傾 45° を 1 とする。太ももの前 ← 膝、お尻と太ももの裏 ← 股関節（同じ値）、背骨に沿った筋肉 ← 上体（と重さ）が股関節のまわりに作るモーメント、ふくらはぎ ← 足首。係数と基準は、仕様書の式に合わせて決めた目安で、文献の値ではない
  - 伸びながら / 縮みながら: 関節の角度の変わる速さ（前後 2 コマ）が 15°/秒を超えて曲がっていくときは「伸びながら」、戻っていくときは「縮みながら」、それ以下は「ほぼ止まって」。どの関節も伸ばす向きに力を出している前提
  - 力の大きさ（Nm・N）は画面に出さない。エルゴと自転車は、ハンドル・ペダルにかかる力が分からないため、負担と要求度を出さない
- **脚・上体・腕が動く順番**（エルゴ。[motionSequence.ts](../src/domain/motionSequence.ts)）: 腰の位置（シート）、上体の傾き（後ろへ開く向きを +）、ひじの曲がりの、前後 2 コマの差から求めた速さ（1 秒あたり）。ドライブ（キャッチ→フィニッシュ）の中で、それぞれの速さがいちばん大きいコマの時刻を、ドライブの % で 1 本ごとに出す。グラフは、1 本（キャッチ→次のキャッチ）を 101 点に引き直し、それぞれの速さをその本の最大で割ってから平均したもの
- **クランクの角度**（自転車。[motionCrank.ts](../src/domain/motionCrank.ts)）: すべてのコマの、腰（股関節）から見た足首の点の位置に円を当て（代数的な最小二乗、Kasa の方法）、中心のまわりの向きを角度とする（上 0°、顔の向き 90°）。腰から見るのは、手持ちでカメラが動いても崩れにくくするため。斜めから撮ると円が楕円に見えるので、点の広がり（共分散）で縦横をそろえてから当て、上と前の向きも同じ変換で移して基準にする。軌跡の縦横比が 0.2 未満（ほとんど線）か、そろえた後の点と円の距離の二乗平均が半径の 30% を超えたら出さない。角度の変化を合計して負なら（顔の向きの推定が逆、または後ろ向きにこいだ）、回る向きに増えるように入れ替え、「足首の点が後ろ向きに回っているように推定された」と注意を出す（実際に後ろ向きにこぐことはまれなので、推定モデルの取り違えを疑う）。ペダルやクランクそのものは検出しておらず、こぐ向きも回転数も、カメラ側の足首の点の動きだけから決めている。クランクの角度 10° ごとに、1 回転の中のコマの値の平均と標準偏差を求める。足首はペダルの軸から離れているため、クランクそのものの角度とは少しずれる
- **バーの軌道**（スクワット。[motionBar.ts](../src/domain/motionBar.ts)）: 持つ重さを入れたときだけ。カメラ側の手首の点をバーの位置とみなす（バーを握っている前提で、プレートは検出しない）。前後は足の真ん中（かかととつま先の中点）からの距離（前が +）、高さはかかとから。長さは重心と同じ換算（身長が仮定なら目安）。1 回ごとに、前後の位置の最大と最小の差（前後のぶれ）、いちばん深いところの前後の位置、立ち上がる間に上がった高さ ÷ 時間（平均の速さ）、上向きの速さの最大（前後 2 コマの差）
- **目安**: 自転車の下死点の膝に、Holmes, Pruitt, Whalen (1994, Clinics in Sports Medicine) の 25〜35° を出典つきで示す。この値は止まった姿勢で角度計を当てて測る方法のもので、こいでいる動画から求めた見かけの角度とは測り方が違うことを書く。良し悪しは判定しない
- **筋肉の場所**: 種目ごとに、一般に主に使われる筋肉（スクワット: 太ももの前・お尻・太ももの裏・背骨に沿った筋肉、エルゴ: それに背中の上部・脇と腕の前を足したもの、自転車: 太ももの前・お尻・太ももの裏・ふくらはぎ）のある場所を、3D の体の骨の重みと面の向き（前・後ろ）で色分けする。教育用の例で、測った値ではない
- **撮った向き**（[motionFrontal.ts](../src/domain/motionFrontal.ts)）: すべてのコマの、左右の股関節の間隔 ÷ 胴の長さ（画面の上）の中央値が 0.2 以下なら横。そうでなく、推定モデルの 3D で左右の股関節を結ぶ線が画面の横向きから 30° 以内（中央値）で、腰の幅の比が 0.3 以上なら、正面か後ろ（鼻が両耳の中点より手前なら正面、奥なら後ろ）。どちらでもなければ斜め。スクワットは、正面・後ろなら squat_front、それ以外なら squat で計算する（記録の種目もそれに合わせる）
- **正面・後ろから撮ったスクワット**: 推定モデルは後ろから撮ると体の左右を取り違えやすいので、左右の組（耳・肩・ひじ・手首・股関節・膝・足首・かかと・足先）ごとに画面の上の位置で分け、後ろから撮ったときは画面の左を、正面から撮ったときは画面の右を体の左とする。コマごとの値（傾きを戻したピクセル座標）:
  - 深さ: 股関節の中点〜足首の中点の高さから、横からと同じ式で求める
  - 腰の横ずれ: 股関節の中点の、足首の中点からの横の位置 ÷ 足首の間隔 × 100（体の左が +）
  - 膝の間隔 ÷ 足首の間隔: 左右の膝の横の間隔 ÷ 左右の足首の横の間隔
  - 左右の膝の外への開き: それぞれの膝の、同じ側の足首からの横の位置（外が +）÷ 足首の間隔 × 100
  - 肩の傾き: 左右の肩を結ぶ線の水平からの角度（体の左が上がると +）
  - 1 回ごとに、いちばん深いところの値と、腰の横ずれの 0 からいちばん離れた値、膝の間隔のいちばん狭い値を出す。区切り方は横からと同じ
  - 骨盤の傾きは出さない（人形の動画で、腰が横にずれると、傾いていないのに 4° ほど傾いて見えたため）
  - 3D は、左右と上下を画面の上の点（体の左右に付け替える）から、前後を骨の長さから組み立てる（下の「3D の体の動かし方」）
- **3D の体の動かし方**（[mannequin.ts](../src/three/mannequin.ts)、[motionPose.ts](../src/domain/motionPose.ts)）:
  - 座って行う種目（エルゴ・自転車）は、両股関節の中点を測った位置に置いて固定し、脚と腕は骨の長さを保ったまま、足首・手首が測った位置に届くように曲げる（2 本の骨の逆運動学。膝・ひじは測った膝・ひじの側へ、前後・上下の面の中で曲げる）。届かないときは、その向きにまっすぐ伸ばす。立って行う種目は、これまでどおり関節の向きを合わせ、両足首の中点を置く
  - 横から撮った記録の左右の位置は、標準の体の幅（体の高さを 1 として、肩 0.11・ひじ 0.125・手首 0.13・股関節 / 膝 / 足首 0.06 など）で固定する。推定モデルの奥行き（左右）は横からの映像では当てにならず、コマごとに使うと体がくねくね揺れ、点ごとの中央値でも脚が大きく開いて見えたため（座った姿勢では体の高さの換算も外れていた）
  - 正面・後ろから撮ったスクワットの前後の位置は、骨の長さから組み立てる。太もも・すね・胴・上腕・前腕の画面の上の長さの、長い方から 1 割の値（立っているとき）をその骨の長さとし、見かけが短くなった分だけ前後に傾いているとする（すねは膝が足首より前、太ももは腰が膝より後ろ、胴は肩が腰より前。腕の前後の向きだけは推定モデルの奥行きの符号を使う）。足は長さを体の高さの 0.13 とし、つま先をかかとより前に置く
  - 自転車の奥側の脚は、クランクの角度が 180° ずれたコマ（前後 1 回転ほどの中で、いちばん近いもの）のカメラ側の脚の形を使う（時間で半回転ずらすと、ケイデンスが変わったときに左右のペダルが反対の位置からずれたため）。クランクと歯車はカメラ側に、反対のクランクは奥側に描く
- **3D の位置の基準**: コマごとに、動かない点（自転車は腰、スクワットとエルゴは足首）が中央の位置に来るように全体をずらしてから 3D にする（手持ちでカメラが動いても、体と器具の形がずれないように。その点の本当の小さな動きは消える）
- **真横でない動画**: 「真横の確認」で真横でないと分かった記録は、回数と、真横でなくても使える値（スクワットの深さ・しゃがむ / 立ち上がる時間、エルゴのレート・ドライブ / リカバリーの時間と比、自転車のケイデンス）だけを使える値とし、ほかの値（角度・位置・重心・負担の比・バーの位置など）は灰色にして「真横でないため参考になりません」と示す。重心の線と筋肉の要求度の濃淡は出さない
- **3D**（[src/domain/motionPose.ts](../src/domain/motionPose.ts)）: 前後と上下は、なめらかにしたカメラ側の画面上の点（角度のグラフと同じ点）から求め、左右の脚・腕に同じ値を使う（自転車の奥側の脚だけは、カメラ側の脚の半回転ずれた動き）。スクワットは体の高さ（耳〜かかと）を 1、かかとの高さを床、立っているときの足首を前後の 0 とする。座る種目は脚の長さ ÷ 0.53 を体の高さとし、床には合わせない。器具の形（エルゴのシート・レール・フットプレート、自転車のクランクの円・サドル・ハンドル）は、腰・足首・手首の点の動きから置いた目安。左右の位置だけは、推定モデルの 3D の点を「左右の股関節と肩を結ぶ向き」に当てて取る（横からの映像では奥行きの推定が外れやすいので参考）。3D の点がなければ標準の体の幅を当てる
- **端末の傾き**（[src/domain/tilt.ts](../src/domain/tilt.ts)）: 立ち姿勢の撮影と同じ方法で、撮影中の画面の面内の傾きを平均し、点の座標を画像の中心のまわりに戻す
