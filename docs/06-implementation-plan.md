# 06. 実装計画

| STEP | 内容 | 完了の条件 |
|---|---|---|
| 1 | プロジェクト構成、依存関係、PWA 基盤、デザイン基盤、GitHub Pages への自動デプロイ | `npm run build` が通り、Pages で空のアプリが開く |
| 2 | MediaPipe 導入（WASM・モデルを自サイト配信）、写真入力、骨格オーバーレイ | アップロードした写真に骨格が重なる |
| 3 | 指標計算・不確かさ・品質チェック・姿勢特徴 | 合成ランドマークを使った単体テストが通る |
| 4 | ランドマーク補正 UI と再計算 | 点を動かすと値が変わり、補正前の値と差分が残る（テストあり） |
| 5 | 分析結果画面（事実 / 仮説 / 行動の分離） | 保存したセッションを開き直して同じ表示になる |
| 6 | 履歴保存・履歴一覧・過去比較 | 2 件以上で比較でき、条件差の注意が出る |
| 7 | 運動 / ストレッチ提案と実施記録 | 特徴と比較結果に応じて提案が変わる（テストあり） |
| 8 | 3D 表示と比較 | 正面+側面から作った 3D を回転でき、過去と重ねられる |
| 9 | プライバシー設定、エクスポート / インポート、設定画面、実装状況ページ | JSON の書き出し→削除→読み込みで元に戻る（テストあり） |
| 10 | テスト、ビルド確認、パフォーマンス、既知の制約の整理 | 全テスト通過、README に起動・検証手順と制約 |

## 進め方

- 計算ロジック（`src/domain`）は UI より先に作り、テストで固定してから画面につなぐ
- 3D 画面は遅延読み込みにして、初回の読み込みを軽くする
- 各 STEP の終わりにコミットし、GitHub Pages に反映する
- 実機確認（Android の Chrome）はユーザーが行う。iPhone は実機がないため未確認として扱う

## リスクと対策

| リスク | 対策 |
|---|---|
| スマホで MediaPipe が重い / GPU が使えない | CPU に自動フォールバック。モデルは高精度の 1 種類に絞り、撮影中の確認は 0.6 秒間隔・撮影中と推定中は止める |
| 衣服でランドマークがずれる | 手動補正、撮影ガイドで体のラインが分かる服を案内、信頼度の上限 |
| 撮影条件の違いで比較が崩れる | 端末の傾き・向き・補正有無・信頼度の差を比較画面で注意表示 |
| 基準値がないため「良い / 悪い」を言えない | 測定のばらつきを超えるかで判定し、自分の過去との比較を主にする |
| 運動メニューの安全性 | 低負荷の一般的なメニューに限定し、中止条件・やってはいけない条件を全メニューに付ける。専門家の監修は未実施であることを明記 |
