## 2. 手動での確認（実機）

公開 URL: GitHub Pages（README を参照）。Android の Chrome で開く。

1. **初回**: オンボーディングが表示される。年齢に 5 を入れると欄の下にエラーが出て進めない。すべて「あとで入力する」でも最後まで進める
2. **撮影**: 「測る」→ 条件を読み「正面の撮影を始める」。カメラの許可を求められる → 許可
   - ガイド枠・水準器（端末の傾き）・「全身が入っています」の表示が出る
   - タイマー 5 秒で撮影、カウントダウン音が鳴る
   - 正面と横向きを 1 枚ずつ撮る。正面の確認に「横向きは撮らずに分析する」が出ない。分析のあとすぐ結果が出る
   - 撮影画面に「映像 1440×1920」のように出て、右の数字（縦）のほうが大きい
   - 撮り方「鏡の前で自撮り」: 姿見の前でスマホを胸の前に持って撮る。結果に「鏡の前で自撮り」と出て、写真の左右が反転している（自分の右手が画面の左）。腕の前方位置は「評価しません」と出る
   - 2 回目以降: 前回の骨格が破線で重なる。近づく・離れると「前回より大きく / 小さく写っています」と出て、同じ位置に立つと「前回と同じ位置です」になる
   - カメラを拒否した場合、「写真を選ぶ」で続けられる
3. **骨格確認**: 点が体に重なっている。点をドラッグすると指の上に拡大鏡が出る。離すと四角（補正済み）になる。矢印ボタンで 1 画素ずつ動く。「すべて元に戻す」で戻る
4. **側面**: 横向きで撮影。顔の向き（左 / 右）が正しく推定されているか確認し、違えば切り替える
5. **結果**: 事実（実線の帯）・仮説（破線の帯）・行動（黄緑の帯）が分かれて表示される。評価不可の項目は理由付きで出る。指標を開くと計算方法と限界が読める
   - 写真に基準線（鉛直線と肩・股関節の水平線）が重なる。「基準線」で消せる
   - 「ずれの向きと大きさ」のゲージで、向きが写真と同じ並びになっている（正面は写っている人の右が画面の左）
   - プロフィールに身長を入れると、肩の高さの差・位置のずれが cm で出る
   - 横向き: 写真の背中側に輪郭の線が重なり、背中の外形に沿っている。「背中上部の丸み」「腰のすき間の深さ」が項目別の指標に出る。体に沿った服と、ゆったりした服で撮ると値が変わることも確かめる
   - 横向きの特徴（頭部前方位傾向など）は「位置の記録」と出て、「差が見られる」とは出ない。サマリーには正面の特徴と、横向きの位置を記録したことだけが出る
   - 体を斜めに向けて撮る（正面で 45° ほど横を向く、横向きで斜め前を向く）と、「体が斜めを向いているようです」などと出て、その面の項目が「評価できませんでした」になり、値が出ない
   - **ほかの姿勢測定サービスとの照合**: 同じ日・同じ条件で撮った結果と、肩の高さ（上がっている側）・上半身の前傾・頭の前方位置・膝の過伸展の「向き」が一致するか（数値は計算方法が違うので比べない）
5b. **意識した姿勢**: 結果の「意識した姿勢を撮る」→ 自分が良いと思う姿勢で正面（と横向き）を撮る → 「いつもの姿勢と比べる」。結果の「いつもの姿勢と意識した姿勢」に、重ね図・ゲージ・項目ごとの分類・仮説・提案（意識づけ / 体を動かすメニュー）が出る
6. **2 回目**: 同じ条件で再測定 → 「比較」で改善 / 横ばい / 悪化と条件差の注意が出る。横向きの項目は、変わったときに「小さくなった / 大きくなった」と出る（改善・悪化とは出ない）。骨格の重ね表示・並べる・スライダー（写真保存時）が切り替わる
7. **3D**: 結果の画面の上のほうに 3D の体が出て、指で回せる（斜め・正面・横）。「3D を大きく見る」で 3D ビューが開く。人体（グレーのマネキン）が測った姿勢で立つ。プロフィールの性別でモデルが変わる。回転・拡大・視点ボタンが動く。比較から開くと前回が半透明で重なる。「骨格」に切り替えると関節の棒と点になる。スマホでなめらかに回せるか
8. **運動**: メニューを開き「やった」→ 記録。ホームの「今週の記録」に反映される
9. **データ**: 設定で JSON / CSV を書き出し → すべて削除 → JSON を読み込みで戻る
10. **オフライン**: 一度測定した後、機内モードでアプリを開き直しても動く（モデルはキャッシュ済み）
11. **通信**: ブラウザの開発者ツールで、測定中に外部ドメインへの通信がないこと
12. **動き（スクワット）**: ホームの「動きを撮る（スクワット）」→「スクワットを撮る」。スマホを縦向きにして腰の高さに置き、体の真横から 2.5〜3 m 離れて 3〜5 回しゃがむ → 「撮り終える」
    - 撮影画面で「全身が写っています」と傾きが出る。しゃがんだときも頭から足まで入るか
    - 推定は何秒かかったか（コマ数と機種）
    - 結果で、動画と 3D の体が同じ動きで並んで動くか。グラフの縦線が動画と合っているか。コマ送り・0.1 倍などの遅い再生・「n 回目の底」・グラフを触って移る、が使えるか
    - 回の数が実際としゃがんだ回数と合うか。浅くしゃがんだ回・途中で止めた回の扱い
    - 「動画をこの端末に残す」をオフにして撮り、アプリを閉じて開き直すと、3D とグラフだけになるか（オンなら動画も出るか）
    - 同じ日に 2〜3 回撮って、深さ・膝の値がどのくらい揺れるか（「前回との差」が「ばらつきの範囲内」になるか）
13. **動き（エルゴ・自転車）**: 一覧の「ローイングエルゴを撮る」「固定式の自転車を撮る」。スマホを横向きにしてシート〜腰の高さに置き（三脚など、動かさない）、真横から 2.5〜3 m。エルゴは 5 本以上、自転車は 10 回転ほど
    - 本数・回転数が実際と合うか。レート・ケイデンスがエルゴのモニター・サイクルコンピューターの値と近いか
    - 3D の器具の形（シート・レール・クランクの円）が体の動きと合っているか。「撮影の情報」に、フットプレート・レールの前提を使ったかが出るか
15. **重心と負担（スクワット）**: 結果で、動画の重心の点と床への線が体の動きに合って見えるか。「負担比」のグラフと帯、筋肉の要求度の色の濃さが、しゃがむときに濃くなり立つと薄くなるか。身長・体重・持つ重さを入れて「この値で計算し直す」と、札が「入力」に変わり値が変わるか
14. **点を直す・比べる・書き出す**: 結果で「点を直す」→ 動画の上の点を指でドラッグ（ほかの点をつかまずに動かせるか）→ 値が変わり、取り消す / やり直すで戻る。同じ種目を 2 回撮って「前回と並べて比べる」。CSV / JSON を書き出して表計算ソフトで開けるか

### 開発時の確認で済んでいること

- PC のブラウザで、写真の読み込み → MediaPipe の読み込み（自サイトから）→ 推定 → 品質判定 → 骨格確認 の流れ（人物のいない画像で「分析できません」まで）
- 合成データを入れた状態での、結果・比較・推移・3D・運動・履歴・設定の各画面（ゲージ・足の図・写真の基準線・cm の表示、複数枚の平均の表示、意識した姿勢との比較を含む）、補正エディタのドラッグと微調整、保存後の補正し直し、写真保存の同意
- 疑似のカメラ映像での、撮影の流れ、前回の骨格の重ね表示、意識した姿勢の撮影画面、カメラが横長の映像を返すときの頼み方の切り替え（3 通り）、鏡の前で自撮りのときに写真が左右反転して保存されること
- 実在の人の写真: 無料素材サイト（Pexels）の、全身が写った正面の写真 11 枚と横向きの写真 11 枚で、推定 → 品質判定 → 指標 → 特徴までを確かめた（写真はリポジトリに入れていない）
  - 骨格の点が体に沿うこと。全身が入っていない写真・人を検出できない写真は、評価不可・測定不可になった
  - 体が斜めを向いた写真（正面 3 枚、横向き 2 枚）は向きの注意が付き、その面の値を出さなくなった。奥行きから見た肩・骨盤の線の傾きは、正面を向いた写真で約 31° 以下、斜めの写真で約 52° 以上だった（しきい値を 40° にした根拠）
  - 正面を向いた写真では、1 枚あたり 1〜5 個の指標が「差が見られる」になった
  - 横向きの写真 8 枚では、以前の判定だと 8 人全員が「猫背傾向に関連する特徴: 差が見られる」になった。このため横向きは 1 回の測定で判定しない方針に変えた
  - 真横から撮れている 4 枚を左右反転して測り直し、背中の輪郭の指標の値の違いから、輪郭の想定誤差を 0.002 → 0.003 × H に広げた
- 姿勢の説明に使われている写真（正面 1 枚、横向き 4 枚。リポジトリに入れていない）
  - 足元が写っていない 2 枚（正面・横向き）は、以前は全項目が評価不可になっていた。隠れた点・写真の外に少し出た点を推測した位置で計算するようにして、値が出るようにした（推測した点を使う項目の信頼度は「低」）
  - ズボンの裾でかかとが隠れた 2 枚で「足先がはっきり写っていません」と出ていた。欠けた部位を「かかと」と正しく出すようにした
  - 全身が写った横向き 3 枚は、骨格の点と背中の輪郭が体に沿い、左右反転して測り直した値の違いも想定した誤差の範囲だった
- 推測した点の誤差: 全身が写った写真（上の正面 8 枚・横向き 7 枚と、姿勢の説明用の横向き 3 枚）の足元を、足首の高さとすねの中ほどで切り落として測り直した
  - 推測した膝・足首・かかと・足先は、切る前の位置から体の高さの約 4%（足首の高さ）・6%（すねの中ほど）ずれた。これを推測した点の想定誤差（1 方向 4%）にした
  - 切り落とした 36 組すべてで値が出た。切る前との違いは、見込んだばらつきの 0.2〜1.0 倍（指標ごとの二乗平均）だった
  - 正面の判定 160 件のうち 22 件が変わった。21 件は「差が見られる」から「ばらつきの範囲内」へで、足元の点の誤差を広く見込んだため
- 公開されている人物の横向き写真 1 枚での、人の領域の取り出し（写真と同じ大きさのマスクが得られる）、背中の輪郭が外形に沿うこと、2 つの指標と結果画面の描画

- 動き（スクワット）: Blender でマネキンが横向きで 4 回しゃがむ動画（[tools/blender/make_squat_test.py](../tools/blender/make_squat_test.py)、縦長 540×960、30 コマ/秒。骨の関節の位置から求めた正解つき）を、「撮った動画を選ぶ」と同じ処理で解析した
  - 4 回すべてを区切り、注意は出なかった
  - コマごとの正解との差（二乗平均）は、深さ 0.9 ポイント、膝 4.4°、股関節 5.8°、上体 2.9°、すね 1.9°
  - 膝と股関節は小さめに出て、深くしゃがむほど差が大きい。いちばん深い回では、膝 106°（正解 116°）、股関節 98°（正解 104°）、深さ 44%（正解 48%）。推定の点の位置が骨の関節と違うため。上体とすねは正解との差が 3° 以内
  - 結果の画面で、動画（骨格の重ね表示）・3D の体・グラフが同じ時刻で動くこと、「n 回目の底」へ移るボタン、コマ送り、速さの切り替え、動画を端末に残したときに開き直しても動画が出ること

## 3. 既知の制約

| 区分 | 内容 |
|---|---|
| 推定 | MediaPipe の点は外見からの推定で、骨の位置ではない。服装・髪・撮影角度・照明で変わる |
| 推定 | 骨盤の前傾・後傾の角度は測れない（目印がない） |
| 推定 | 背中の輪郭は人の領域の外形で、背骨の形ではない。ゆったりした服・背中にかかる髪・腕の位置で変わる |
| 推定 | 鏡像になった写真（インカメラの設定による）では、左右が入れ替わる可能性がある。アプリ内で撮った写真は鏡像にしていない |
| 判定 | 「差が見られる」の判定は、点の位置誤差を体の高さの 0.5% と仮定した工学的な目安。実際の誤差は人や服装で違う。以前の高精度モードの記録でも前提を下限にし、平均した後の揺れが前提を超えるときだけ広げる |
| 判定 | 横向きの前後の位置（頭・上半身・腕・骨盤帯・膝）と複合スコアは、1 回の測定では判定しない（位置の記録）。0 が良い姿勢とは言えず、ほぼ全員が「差が見られる」になるため。前回から変わったかどうかだけを伝える |
| 推定 | 隠れた点・写真の外に少し出た点は、MediaPipe が推測した位置で計算する。足元を切った写真では、推測した足首などの位置が体の高さの 4〜6% ずれた。写真のぎりぎりの端にある点は、写っている点として扱っても同じくらいずれることがある |
| 判定 | 体が斜めを向いた写真は、その面の値を出さない。正面の向きは奥行きの推定（z）にも頼っていて、ゆったりした服や腕の位置で外れることがある |
| 判定 | 以前の高精度モード（版 0.6 まで）で測った揺れは、続けて撮った約 2 秒の間の推定の揺れだけ。立ち直しや、日をまたいだ体調・服装・撮影位置の違いは含まない |
| 撮影 | 鏡の前で自撮りした写真は、カメラが胸の高さで手持ちになり、スマホを持つ側の肩が上がりやすい。立てかけて傾いた鏡では体が傾いて写り、端末の水準器では分からない |
| 比較 | 意識した姿勢は「その日に自分が良いと思った姿勢」で、毎回同じとは限らない。意識しても残る差の理由（柔軟性・筋力・骨格・意識の向け方など）はこの比較では分からない |
| 判定 | 基準値（正常範囲）は持たない。他人との比較はできない |
| 比較 | 撮影条件（距離・高さ・向き）が違うと、変化と区別できない。条件差は注意表示のみ |
| 動き | 横から見た見かけの角度で、骨の角度ではない。推定の点は骨の関節と位置が違い、正解のある人形の動画では、深くしゃがむほど膝・股関節が小さく出た（いちばん深い回で 6〜10°）。自分の過去の記録と比べる値として扱う |
| 動き | ラックの柱・プレート・器具で脚が隠れると、膝や足首を別の場所に推定することがある（注意は出す）。プレートで頭が隠れても角度には使わないが、3D の頭の向きは崩れることがある |
| 動き | 斜めから撮ったスクワットは、回数・深さ・時間だけが使える。左右の差は、真正面か真後ろ（股関節の線が画面の横向きから 30° 以内）から撮ったときだけ測る |
| 動き | 正面・後ろからの左右の差は、画面の上の見かけの位置。膝のねじれ（内側に回っているか）や、骨盤の傾きは分からない。体の前後の動きは、正面・後ろからは推定モデルの奥行きの推定だけで、3D の前後の形は参考 |
| 動き | 自転車のペダル・クランクは検出していない。回転数・こぐ向き・3D のクランクは、カメラ側の足首の点の動きから決めている。推定モデルが手前と奥の脚を取り違えると、向きが逆に見えることがある（注意を出す） |
| 動き | 自転車のクランクの角度は、腰がサドルの上でほぼ動かない前提。腰が大きく動くこぎ方（立ちこぎなど）では外れる |
| 動き | エルゴ・自転車の膝は、太もも・すねの長さが変わらない前提で置き直した位置（横から見て脚がまっすぐ前後に動く前提）。膝が外に開くこぎ方や、斜めから撮った動画では外れる。エルゴの足首とレールの前提は、スマホを動かさずに撮ったときだけ使う |
| 動き | 自転車の足首の角度は「膝・足首・足先の点」の角度で、靴を履くと足先は靴の先になる。骨の角度や他の測り方の値とは比べられない |
| 動き | 点を直せるのは画面の上の位置だけで、奥行き（3D の左右）は直せない |
| 推定 | 重心・負担の比・要求度は、床からの力や筋肉の働きを測らずに、体節の重さの割合と仮定から求めた推定。正解のある値で確かめていない（人形の動画にも力の正解はない）。足圧中心と左右の配分の仮定を動かした幅は出すが、体節の重さの割合・体の形の違い・奥側の手足の位置・体節の加速度による違いは幅に入っていない |

### 筋肉の体（版 0.20.0）

- **作り方の確認**: 解剖モデル（Z-Anatomy）と、同じ姿勢・寸法に重ねた標準の人体を、正面・横・背面から重ねて描いて位置を見た。関節（肩・ひじ・手首・股関節・膝・足首・指）は一致。肩の上と骨盤の前後は目で見て 1〜2 cm 直した（肩を 1.2 cm 下げ、骨盤を 2 cm 後ろへ）
- **焼けた割合**（その部位の表面のうち、解剖モデルに当たった割合）: 胴と頭 99.5%、腕 98.9%、手 93.2%、脚 100%、足 84.7%。当たらなかった所は、いちばん近い当たった所の色で埋めた（足の指のあいだ・足の裏が多い）
- **画面での確認**（確認用の人形のエルゴの記録、幅 420 px）: 並べて見るの 3D に筋肉の体が出て、横・斜め・後ろの視点で、三角筋・上腕三頭筋・広背筋・大殿筋・腸脛靱帯・前腕の筋・顔の筋が体の正しい側と場所に出ることを見た。「筋肉の体」ボタンが出ること、型の検査と単体テスト 200 件が通ることを確かめた
- **確かめていないこと**: 実機（スマホ）での表示と重さ。凹凸の絵の上下の向き（決まりから決めたが、絵で見比べてはいない）。「主に使う筋肉」を出したときの明るさの見え方。女性・男性の体での見え方（絵は中間の体で焼いた。UV は同じ）。無地への切り替えの見た目
- **限界**: 筋肉の形は標準の解剖モデルのもので、本人のものではない。体の表面に絵を貼っているだけなので、筋肉が動きで膨らんだり縮んだりはしない。解剖モデルは手のひらを前に向けた姿勢なので、前腕の筋は手首の近くで実際の並びからずれる。手と足の指は細かく、絵がにじむ所がある
