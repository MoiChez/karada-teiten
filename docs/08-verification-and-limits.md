## 2. 手動での確認（実機）

公開 URL: GitHub Pages（README を参照）。Android の Chrome で開く。

1. **初回**: オンボーディングが表示される。年齢に 5 を入れると欄の下にエラーが出て進めない。すべて「あとで入力する」でも最後まで進める
2. **撮影**: 「測る」→ 条件を読み「正面の撮影を始める」。カメラの許可を求められる → 許可
   - ガイド枠・水準器（端末の傾き）・「全身が入っています」の表示が出る
   - タイマー 5 秒で撮影、カウントダウン音が鳴る
   - 正面と横向きを 1 枚ずつ撮る。正面の確認に「横向きは撮らずに分析する」が出ない。分析のあとすぐ結果が出る
   - 撮影画面に「映像 1440×1920」のように出て、右の数字（縦）のほうが大きい
   - 撮り方「鏡の前で自撮り」: 姿見の前でスマホを胸の前に持って撮る。結果に「鏡の前で自撮り」と出て、写真の左右が反転している（自分の右手が画面の左）。腕の前方位置は「評価しません」と出る
   - 2 回目以降: 前回の骨格が破線で重なる。近づく・離れると「前回より大きく / 小さく写っています」と出て、同じ位置に立つと「前回と同じ位置です」になる
   - カメラを拒否した場合、「写真を選ぶ」で続けられる
3. **骨格確認**: 点が体に重なっている。点をドラッグすると指の上に拡大鏡が出る。離すと四角（補正済み）になる。矢印ボタンで 1 画素ずつ動く。「すべて元に戻す」で戻る
4. **側面**: 横向きで撮影。顔の向き（左 / 右）が正しく推定されているか確認し、違えば切り替える
5. **結果**: 事実（実線の帯）・仮説（破線の帯）・行動（黄緑の帯）が分かれて表示される。評価不可の項目は理由付きで出る。指標を開くと計算方法と限界が読める
   - 写真に基準線（鉛直線と肩・股関節の水平線）が重なる。「基準線」で消せる
   - 「ずれの向きと大きさ」のゲージで、向きが写真と同じ並びになっている（正面は写っている人の右が画面の左）
   - プロフィールに身長を入れると、肩の高さの差・位置のずれが cm で出る
   - 横向き: 写真の背中側に輪郭の線が重なり、背中の外形に沿っている。「背中上部の丸み」「腰のすき間の深さ」が項目別の指標に出る。体に沿った服と、ゆったりした服で撮ると値が変わることも確かめる
   - **ほかの姿勢測定サービスとの照合**: 同じ日・同じ条件で撮った結果と、肩の高さ（上がっている側）・上半身の前傾・頭の前方位置・膝の過伸展の「向き」が一致するか（数値は計算方法が違うので比べない）
5b. **意識した姿勢**: 結果の「意識した姿勢を撮る」→ 自分が良いと思う姿勢で正面（と横向き）を撮る → 「いつもの姿勢と比べる」。結果の「いつもの姿勢と意識した姿勢」に、重ね図・ゲージ・項目ごとの分類・仮説・提案（意識づけ / 体を動かすメニュー）が出る
6. **2 回目**: 同じ条件で再測定 → 「比較」で改善 / 横ばい / 悪化と条件差の注意が出る。骨格の重ね表示・並べる・スライダー（写真保存時）が切り替わる
7. **3D**: 結果から「3D で見る」。人体（グレーのマネキン）が測った姿勢で立つ。プロフィールの性別でモデルが変わる。回転・拡大・視点ボタンが動く。比較から開くと前回が半透明で重なる。「骨格」に切り替えると関節の棒と点になる。スマホでなめらかに回せるか
8. **運動**: メニューを開き「やった」→ 記録。ホームの「今週の記録」に反映される
9. **データ**: 設定で JSON / CSV を書き出し → すべて削除 → JSON を読み込みで戻る
10. **オフライン**: 一度測定した後、機内モードでアプリを開き直しても動く（モデルはキャッシュ済み）
11. **通信**: ブラウザの開発者ツールで、測定中に外部ドメインへの通信がないこと
12. **歩き方（試作）**: ホームの「歩き方を測る（試作）」→「歩き方を撮る」。スマホを横向きにして腰の高さに置き、3m 離れた線の上を往復して歩く
    - 撮影画面で「全身が写っています」と傾きが出る。横向きに置いたとき、映像の人が横倒しにならずに推定される
    - 推定は何秒かかったか（コマ数と機種）。結果の 3D で、マネキンが自分の歩き方に近い動きで歩くか
    - 同じ日に 2〜3 回撮って、テンポ・歩幅・上体の値がどのくらい揺れるか（「前回との差」が「ばらつきの範囲内」になるか）
    - 片道だけ・ななめに歩いたときに注意が出るか

### 開発時の確認で済んでいること

- PC のブラウザで、写真の読み込み → MediaPipe の読み込み（自サイトから）→ 推定 → 品質判定 → 骨格確認 の流れ（人物のいない画像で「分析できません」まで）
- 合成データを入れた状態での、結果・比較・推移・3D・運動・履歴・設定の各画面（ゲージ・足の図・写真の基準線・cm の表示、複数枚の平均の表示、意識した姿勢との比較を含む）、補正エディタのドラッグと微調整、保存後の補正し直し、写真保存の同意
- 疑似のカメラ映像での、撮影の流れ、前回の骨格の重ね表示、意識した姿勢の撮影画面、カメラが横長の映像を返すときの頼み方の切り替え（3 通り）、鏡の前で自撮りのときに写真が左右反転して保存されること
- 公開されている人物の横向き写真 1 枚での、人の領域の取り出し（写真と同じ大きさのマスクが得られる）、背中の輪郭が外形に沿うこと、2 つの指標と結果画面の描画

- 歩き方: Blender でマネキンが往復して歩く動画（[tools/blender/make_walk_test.py](../tools/blender/make_walk_test.py)、テンポ 110 歩/分）を作り、「撮った動画を選ぶ」と、その動画を疑似のカメラ映像にした「カメラで撮る」の両方で、推定→計算→保存→結果→3D 再生まで通ること。テンポは両方で 110.5・110.7 歩/分、ほかの値も両方でほぼ同じ（歩幅 59%・58%、上体 −5.2°・−5.4°、頭 13.9°・13.8°、腕 36°・37°）。歩幅は骨の位置から求めた 65% より小さく出る（推定の点の位置が骨の関節と違うため。自分の過去と比べる値として扱う）

- 歩き方（実在の人物）: 無料素材サイト（Pexels・Pixabay）の、人が歩く動画 6 本で「撮った動画を選ぶ」を確かめた（動画はリポジトリに入れていない）
  - 壁の前を横から歩く人: 骨格の点が体に沿い、検出した歩の瞬間が両足の最も開いたコマ、谷が両足のそろったコマと一致した
  - カメラから斜めに遠ざかる人（4 本）: 「カメラに近づく・遠ざかる向き」の理由で測定不可になった。このうち 1 本で、1 コマの推定の乱れから映像を 180° 回してしまう不具合が見つかり、5 コマの多数決に直した
  - カメラが人を追って動く（パン）動画: 歩の検出は合うが、腰の進みが画面の動きと混ざり、通過の区切りが乱れる
  - スローモーションの動画: 歩の位置は合うが、テンポは動画の時間で数えるため実際より遅く出る（アプリでは見分けられない）

### 開発時に確認できていないこと

- 実際の人物写真での推定精度（骨格の点は人物写真で確かめていない。背中の輪郭は 1 枚で確かめただけ）
- 背中の輪郭の指標の繰り返しの揺れ（同じ日に立ち直して撮ったときの値の差）と、服装による違いの大きさ
- 実際のカメラでの撮影（開発用ブラウザでは疑似の映像のみ）、端末の傾きセンサー、タイマー音・音声の案内
- 実際の人物での写真ごとの揺れの大きさ、前回の位置の案内が実用的に合わせやすいか
- 高精度モデルの推定速度（スマホでは 1 枚に 1 秒前後かかる可能性がある）
- 鏡の前で自撮りした写真での推定のしやすさ（スマホと手が胸の前に写る）
- 歩き方: 実際の人の歩く動画での推定の精度と速さ、スマホのカメラでの撮影（開発用ブラウザでは疑似の映像のみ）、横向きに置いたときの映像の回し方、値の繰り返しの揺れ
- iPhone（Safari）での動作

## 3. 既知の制約

| 区分 | 内容 |
|---|---|
| 推定 | MediaPipe の点は外見からの推定で、骨の位置ではない。服装・髪・撮影角度・照明で変わる |
| 推定 | 骨盤の前傾・後傾の角度は測れない（目印がない） |
| 推定 | 背中の輪郭は人の領域の外形で、背骨の形ではない。ゆったりした服・背中にかかる髪・腕の位置で変わる |
| 推定 | 鏡像になった写真（インカメラの設定による）では、左右が入れ替わる可能性がある。アプリ内で撮った写真は鏡像にしていない |
| 判定 | 「差が見られる」の判定は、点の位置誤差を体の高さの 0.5% と仮定した工学的な目安。実際の誤差は人や服装で違う。高精度モードでも前提を下限にし、平均した後の揺れが前提を超えるときだけ広げる |
| 判定 | 以前の高精度モード（版 0.6 まで）で測った揺れは、続けて撮った約 2 秒の間の推定の揺れだけ。立ち直しや、日をまたいだ体調・服装・撮影位置の違いは含まない |
| 撮影 | 鏡の前で自撮りした写真は、カメラが胸の高さで手持ちになり、スマホを持つ側の肩が上がりやすい。立てかけて傾いた鏡では体が傾いて写り、端末の水準器では分からない |
| 比較 | 意識した姿勢は「その日に自分が良いと思った姿勢」で、毎回同じとは限らない。意識しても残る差の理由（柔軟性・筋力・骨格・意識の向け方など）はこの比較では分からない |
| 判定 | 基準値（正常範囲）は持たない。他人との比較はできない |
| 比較 | 撮影条件（距離・高さ・向き）が違うと、変化と区別できない。条件差は注意表示のみ |
| 歩き方 | カメラを固定して撮った、実時間の動画が前提。人を追ってカメラを動かした動画では通過の区切りが乱れ、スローモーションの動画ではテンポが遅く出る。カメラに近づく・遠ざかる向きに歩いた通過は使わない |
| 歩き方 | 歩幅は「足首どうしの最も開いた距離 / 股関節〜足首」で、かかと同士の一般的な歩幅とは違う。奥側の足首の推定がずれやすく、1 歩ごとの値が交互に大きく・小さく出ることがある |
| 3D | 2 枚の写真の合成で、同時に撮った立体ではない。奥行きは側面写真、左右は正面写真から |
| 3D | 人体は全員共通の標準の体で、本人の体型ではない。関節の向きだけを反映し、骨の長さ・骨盤の前後の傾き・背中の丸みは反映しない |
| 運動 | メニューは一般的な低負荷のもので、専門家の監修は受けていない。文章のみ（動画・イラストなし） |
| 保存 | データはブラウザ内のみ。ブラウザのデータ削除や端末変更で消える（書き出しで対策） |
| 画面 | ダークモードは未対応 |
| フォント | 数字と英字は IBM Plex Sans JP、日本語は端末の標準フォント（読み込みを軽くするため） |

## 4. 次フェーズの提案

優先度の高い順。

1. **実機での精度確認と閾値の調整**: 同じ人が同じ日に数回、立ち直して測り、値の差から `LANDMARK_SIGMA_FRACTION`（現在 0.5%）が実態に合っているかを確かめる
2. **運動メニューの監修とイラスト**: 理学療法士・トレーナーの確認を受け、手順のイラストか短い動画を付ける
3. **リマインダー**: 再測定日や運動の通知（PWA の通知、または OS のカレンダー登録）
4. **骨盤の目印の手動入力**: 側面写真で骨盤の前後の目印をユーザーが置けるようにし、骨盤の前後傾を参考値として出す
5. **詳細モード（12 枚測定）**: 腕を上げる・前屈など、動きを含む姿勢の測定
6. **ダークモード**と、文字サイズの拡大設定
7. **データの引き継ぎ**: 端末間でのエクスポート / インポートの簡易化（QR やファイル共有）。クラウド同期はプライバシー設計を見直してから
